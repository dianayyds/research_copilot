# DeepResearch Copilot 项目逐字稿

## 一、项目背景

这个项目叫 DeepResearch Copilot，是我个人做的一个面向科研的深度研究 Agent，服务的是我自己读文献、做课题调研的场景。它的私有知识库就是我攒的文献库和项目文档，评测用的是我自建的一套语义通信 benchmark，所以整个数据来源、ground truth 都是我一个人能独立搞定的。

它要解决的问题是：一个复杂的科研问题，不是检索一次就能答清楚的。比如"某个方向现在主流的技术路线有哪几条、各自的前提假设和短板是什么"——这种问题得拆成好几个子问题，每个子问题查完还会牵出新的疑点，得顺着线索一层层往下追。传统的 RAG 是"一次召回、一次回答"，面对这种问题就是浅尝辄止。我做的这个系统，核心就是让 Agent 自己决定怎么研究、查到什么程度算够，然后在很长的研究链路上把上下文管住，最后给一份每个结论都能指回原文出处的报告。

## 二、整体架构

系统的骨架是一张用 LangGraph StateGraph 搭的带环图，核心就是一个全局状态加四个节点，节点之间用条件边流转。

先说状态。贯穿整张图的是一个全局的 **ResearchState**，用 TypedDict 定义，里面主要几块：原始问题、拆出来的子问题列表和当前正在查的那个子问题、每个子问题已收集的证据摘要、scratchpad 笔记，还有迭代轮数、token 预算这些控制字段。这里有个关键设计——**搜索到的网页和文献只把摘要加来源 URL 写进 state，原文外置到 MinIO**，要看原文再按 URL 去捞。一次深度研究得读几十篇文献，原文全塞进 state、再顺着进模型上下文，几轮就爆了。

然后是四个节点，各管一段：

**Plan 节点**管规划。第一次进来，它把大问题拆成一组子问题、生成研究大纲写进 state；后面如果被路由回来，它做的是重规划——根据已经拿到的证据补子问题、改大纲。

**Retrieve 节点**管检索。针对 state 里当前那个子问题，调 Hybrid RAG 检索工具做多路召回；如果上一轮判断是召回质量不行，它会先套一个改写策略——Query Rewrite、HyDE 或 Step-back——再检索。召回结果的摘要写回 state。

**Reflect 节点**是整张图的决策中枢。它读一遍新召回的证据、判断相关性，做 gap detection 看当前子问题还缺什么，然后产出一个路由决策：这个子问题还得接着查、还是该换下一个子问题、还是得回去重规划、还是所有子问题都够了可以收尾。停止准则也在这里算——证据的边际收益低了，或者到了最大轮数、token 预算上限，就置终止标志。

**Synthesize 节点**管收尾。汇总所有子问题的证据，做 citation grounding，生成带引用的报告。

流转靠条件边，决策点集中在 Reflect 出来的那条边上，整体是这样走的：

- 入口 → Plan → Retrieve → Reflect
- Reflect 之后是一条条件边，按它的路由决策分四个去向：证据不足、还有预算 → 回 Retrieve，带改写重查同一个子问题；发现规划有盲区 → 回 Plan 重规划；当前子问题够了、还有没查的子问题 → 回 Retrieve 切到下一个；所有子问题都充分、或者触达预算上限 → 去 Synthesize
- Synthesize → END

所以"带环"就体现在 Reflect 能把流程打回 Retrieve 或 Plan，循环几轮不是写死的，是 Reflect 每轮根据证据现状决定的。

## 三、任务拆解与自适应重规划

进来一个问题，Agent 不会马上去检索，而是先规划。它把复杂问题拆成若干子问题，生成一个研究大纲，相当于先列个调查提纲。

但光在开头拆一次不够。真实的研究是"边查边发现新问题"的——你查着查着会发现原来的提纲漏了一个关键分支，或者某个子问题其实需要拆得更细。所以我做了**自适应重规划**：每轮证据到手后，Agent 会回看当前的证据和原计划，如果发现盲区，就动态补子问题、改研究计划，而不是死守最初那份提纲。这是 Plan-and-Execute 里"计划可被执行结果反过来修正"的思路。

## 四、迭代检索闭环与 agentic RAG（核心之一）

这是系统的第一个核心，也就是所谓的 agentic RAG——检索不再是"一次召回、一次回答"，而是 Agent 在一个循环里自主决定查几轮、每轮怎么查。对每个子问题，Agent 走的是这样一个循环：**检索 → 阅读并判断相关性 → gap detection → 改写或换角度再检索**，直到这个子问题的证据充分。

检索这一步调的是我封装好的 Hybrid RAG 检索工具，一会儿细讲。检索回来之后，Agent 不是照单全收，而是要**读一遍、判断相关性**——这批召回到底命不命中当前子问题。

然后是 **gap detection**，这是闭环的关键——判断"还缺什么"。是某个环节没有证据支撑？还是召回的东西都不对路？根据缺口的类型，决定下一步怎么补。

如果是召回质量不行，就触发**检索改写**再查一遍。这里有三个检索增强策略——Query Rewrite、HyDE、Step-back——不是每次检索都一股脑全上，而是循环内按需触发：Agent 发现召回不足了，才选一个合适的改写策略重检索。比如召回太空泛就用 Step-back 抽象一层，query 和文献表述对不上就用 HyDE 先生成一段假设答案再检索。

还有一条是**信源追溯递归**：对一些关键数据，光知道二手转述不够，得回溯到原始出处。所以对关键结论我会顺着引用链往上递归找源头，但设了最多 N 层的上限，防止无限递归下去。

## 五、长链路上下文管理（核心之二）

这是系统的第二个核心，也是深度研究和普通 RAG 最不一样的地方。研究链路一长，几十轮下来，上下文要么爆、要么被早期的噪音带偏。我从几个层面管这个事。

**第一层是三层记忆**。working 是当前的 ResearchState，也就是这一轮正在用的工作记忆；episodic 是本轮研究里走过的步骤和发现，相当于研究过程日志；semantic 是跨会话沉淀下来的领域知识和我的偏好。这三层各管一段生命周期的信息。

**第二层是中间结果的 compaction 和摘要**。不是所有中间产物都值得常驻主上下文。我会把阶段性的检索结果压缩成摘要，只让高价值信息进主上下文，原始的细节留在外置存储里，需要再捞。

**第三层是 scratchpad 结构化记笔记**。Agent 每走一步，把关键发现沉淀成结构化的可回捞条目，而不是让全量对话历史一直堆在上下文里。后面要用某个早期发现，从 scratchpad 里按条目捞，而不是翻整段历史。

**第四层是矛盾和污染处理**。深度研究里不同来源经常打架，比如两篇文献对同一个数据给了不同结论。我的做法是**来源冲突就显式标注出来**，不在检索阶段擅自取舍，而是把矛盾带到最后的综合环节去权衡。这样能避免早期一个错误结论被当成事实、一路把后续研究带偏。

## 六、Hybrid RAG 检索工具

检索这块是 Agent 循环里的检索工具，Retrieve 节点调的就是它。

它是**多路召回加重排**：BGE-M3 做向量检索、走 Qdrant；BM25 加 jieba 做中文关键词检索；两路召回的结果再用 BGE Reranker 统一重排。向量负责语义、关键词负责精确命中术语，重排再把两路融合排序。

这套我是有量化的。在我自建的语义通信 benchmark 上，Top-1 命中率从 80% 提到了 93.3%，MRR@5 从 0.869 提到 0.967，Coverage@5 做到 100%，还有一个 Top-1 干扰漂移率——就是最相关的结果被干扰项挤掉的比例——从 13.3% 降到了 6.7%。

## 七、可溯源引用

深度研究的报告，最怕的就是"看着有理有据、其实是编的"。所以我在综合阶段做了 **citation grounding**：汇总各子问题证据生成报告时，**每个关键结论都要能指回它的来源**，绑定到具体的召回证据和原文 URL。如果一个结论在召回证据里找不到支撑，就当它是疑似幻觉，不让它进最终报告。这样出来的报告是可溯源、可复核的。

## 八、成果与工程

整个系统是我一个人从方案到实现完整交付的，存储用 Qdrant 存向量、MinIO 存原文和中间产物、Redis 存会话和检查点，后端 FastAPI。

端到端的评测我是这么搭的。因为没有现成的科研深度研究评测集，我自己攒了一套：从私有文献库里挑出 50 道需要多跳、多子问题才能答清楚的复杂研究问题，每道题我人工读源文献、标注两样东西——一份"完整答案应该覆盖哪些关键事实点"的清单，和这道题应该命中的源文献，这份标注就是 ground truth。

指标我盯四个。第一个是**平均检索轮数**，看它是不是真自适应——测下来平均 4.3 轮，简单问题一两轮就收、复杂的能到八九轮，说明轮数确实跟着问题难度走、不是写死的。第二个是**事实覆盖率**，用 LLM-as-judge 把报告和我标的关键事实点比对、算命中比例，对照组是单次 RAG 直接答，58% 提到了 84%。第三个是**引用忠实率**，把报告里每一条带引用的结论拎出来、核对它引的那段原文到底支不支撑这个结论，LLM 判定加人工抽检校准，做到 91%。第四个是**幻觉率**，就是报告里没有来源支撑的事实性陈述占比，从单次 RAG 的 18% 压到了 6%。

这套评测还有个后续用途——它正好接上我的第二个项目，拿这套研究环境去做 RL 训练，这里的事实覆盖率、引用忠实率就直接当 reward 和离线评测用。

## 附：可能的面试问题

**Q：为什么用 LangGraph 带环图，而不是固定工作流？**
科研问题深浅差异极大，有的一轮就够、有的要追溯十几轮，固定 pipeline 没法自适应。带环图用条件边让 Agent 每轮自己判断继续还是终止，迭代轮数由问题本身决定，这才是 agentic 的做法。

**Q：agentic 循环怎么保证停得下来？**
两道闸。软的一道是 Reflection 判断证据充分性和继续检索的边际收益，收益低就停；硬的一道是最大迭代轮数加 token 预算兜底，到上限强制停。

**Q：长链路上下文怎么不爆？**
从存储和记忆两头管。存储上，网页文献只把摘要和 URL 进 state、原文外置 MinIO；记忆上，三层记忆分管不同生命周期，中间结果做 compaction 摘要，关键发现进 scratchpad 结构化回捞，不让全量历史常驻上下文。

**Q：怎么防止研究报告里的幻觉？**
综合阶段做 citation grounding，每个关键结论必须能绑定到召回证据和原文出处，找不到支撑的结论当疑似幻觉剔除。来源之间有矛盾就显式标注、留到综合环节权衡，不在检索阶段擅自取舍。

**Q：这个项目和你第二个 RL 项目是什么关系？**
这套研究 Agent 环境就是第二个项目的 RL 训练环境。这个项目里的推理模型现在用的是强模型打通链路，第二个项目用 GRPO 训出的小模型策略可以直接替换进来当决策底座；而这个项目里本来就有的降级策略、reranker 分数这些判断逻辑，回传训练 loop 就是现成的 dense reward。
